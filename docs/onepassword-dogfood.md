# 1Password dogfood (Milestone 6)

Prove that the same portable `pade.yaml` can resolve capabilities through a **second credential-manager product** (1Password) without changing the repository capability declaration.

PADE shells out to the 1Password CLI (`op read`).

## Two ways to try it

| Goal | Command |
|------|---------|
| CI / no 1Password account | `make dogfood-onepassword` (uses [scripts/fake-op.sh](../scripts/fake-op.sh)) |
| **Your machine + real `op`** | `make dogfood-onepassword-live` |

## Live demo on your laptop (recommended)

Prerequisites:

1. Install the [1Password CLI](https://developer.1password.com/docs/cli/get-started/)
2. Sign in: `op signin`
3. Build PADE once: `make build` (or let the Make target do it)

Then from the repo root:

```bash
make dogfood-onepassword-live
```

That will:

1. Verify `op` is on `PATH` and signed in
2. Create (or reuse) a disposable vault `pade-demo` and item `pade-google-analytics` with **fake** demo field values
3. Write local bindings to `.pade/bindings.onepassword.live.yaml` (gitignored; refs only, no secret values in git)
4. Run `pade capabilities` + `pade exec … ./scripts/ga-summary` with ambient `GA_*` unset, so values must come from 1Password
5. Assert plan/capabilities JSON never contain the seeded secret substrings

Optional overrides:

```bash
OP_VAULT=Personal OP_ITEM=my-ga-item make dogfood-onepassword-live
SKIP_SEED=1 PADE_ONEPASSWORD_BINDINGS=$HOME/.config/pade/bindings.yaml make dogfood-onepassword-live
PADE_OP_BIN=/usr/local/bin/op make dogfood-onepassword-live
```

## Fake-op smoke (CI)

```bash
make dogfood-onepassword
```

Uses fixed `op://pade-demo/...` refs and [scripts/fake-op.sh](../scripts/fake-op.sh). No real 1Password account required.

## Bindings shape

```yaml
provider: onepassword
onepassword:
  refs:
    GA_PROPERTY_ID: "op://pade-demo/pade-google-analytics/property_id"
    GOOGLE_APPLICATION_CREDENTIALS: "op://pade-demo/pade-google-analytics/credentials_path"
```

| File | Role |
|------|------|
| [bindings.onepassword.example.yaml](../examples/demo-project/bindings.onepassword.example.yaml) | Shared example refs (fake-op) |
| [alice.onepassword.bindings.yaml](../examples/demo-project/identities/alice.onepassword.bindings.yaml) | Alice refs (fake-op) |
| [bob.onepassword.bindings.yaml](../examples/demo-project/identities/bob.onepassword.bindings.yaml) | Bob refs (fake-op) |
| `.pade/bindings.onepassword.live.yaml` | Generated by the live Make target (local only) |

## Manual live commands

If you already have vault/item/field refs:

```bash
# ~/.config/pade/bindings.yaml or .pade/bindings.yaml
./bin/pade capabilities -f examples/demo-project/pade.yaml --bindings .pade/bindings.onepassword.live.yaml
./bin/pade exec -f examples/demo-project/pade.yaml \
  --bindings .pade/bindings.onepassword.live.yaml \
  --capability google-analytics.read \
  -- ./examples/demo-project/scripts/ga-summary
```

## CI

GitHub Actions runs the **fake-op** path under Smoke → **1Password dogfood** (`dogfood-onepassword: ok`). The live target is local-only (needs your signed-in CLI).

## Out of scope

- Embedding the 1Password SDK in portable packages (CLI adapter only)
- Service-account / Connect server production auth
- Claiming PADE replaces 1Password
